Проверка карточек перед публикацией.

Запуск: `npm run check:data`. Проверка работает без браузера и завершает процесс с ошибкой, если найдены дефекты. `node tools/check_cards.js --json` выводит тот же результат в JSON.

Сейчас проверяются викторина и «Пары»:

- Непустые вопросы, известные темы и сложность 1–5.
- Четыре непустых и различающихся варианта ответа. Знаки минуса, ударения и значимый регистр сохраняются.
- Устойчивые ID вопросов и их уникальность. Пунктуационные варианты одной формулировки в одной теме требуют редакторского разбора.
- Формат ссылки на источник и даты проверки. У статуса `reviewed: true` обязательны источник и дата.
- Минимум 18 пар в каждой теме, непустые значения и отсутствие повторов по каждой стороне внутри темы.

Автоматическая проверка не подтверждает фактическую правильность ответа, правдоподобие неверных вариантов и соответствие сложности. Она также не находит все смысловые повторы. Эти решения принимает редактор.

Формат вопроса:

```js
Q('sport', 3, 'Вопрос с точными условиями?',
  'Верный ответ', 'Неверный ответ 1', 'Неверный ответ 2', 'Неверный ответ 3', {
    source: 'https://адрес-первичного-источника',
    checkedAt: '2026-11-13',
    reviewed: true,
    explain: 'Короткое объяснение правильного ответа.'
  });
```

Первый вариант в исходниках — правильный; интерфейс перемешивает ответы. Метаданные передаются последним аргументом. Ставить `reviewed: true` следует после чтения источника и проверки всех вариантов. Наличие ссылки само по себе не означает, что вопрос проверен.

Для изменяемого факта лучше указать дату или историческое событие в самом вопросе. Например, вопрос о спортивном рекорде следует привязать к дате, а не спрашивать о рекордсмене без уточнения времени. Для спорных определений и фактов с разными методиками измерения нужны точные условия.

ID вычисляется из темы и формулировки. Перестановка вопросов, изменение сложности, ответа или метаданных не меняют ID. Существенная правка формулировки или перенос в другую тему создают новый ID. Перечитывать данные для выдачи ID вручную не требуется; коллизии или совпадающие формулировки остановят проверку.

История показа теперь хранит ключи карточек вместо позиций в массивах. Прежняя числовая история начинает новый цикл один раз после обновления; это позволяет избежать ошибочного сопоставления после удаления вопросов. Настройки и избранное сохраняются. Прежние записи о скрытых вопросах с неизменённым содержимым также учитываются.

При редакторской проверке вопроса:

1. Проверить, что условия допускают один правильный ответ.
2. Сверить ответ с первичным источником, записать ссылку и дату.
3. Проверить, что остальные варианты неверны при этих условиях и не являются синонимами правильного.
4. Найти похожие формулировки в базе и согласовать сложность.
5. Написать объяснение, если оно помогает понять ответ; проставить редакторский статус.
6. Запустить `npm run check:data` и `npm run test:cards`.
